# WinMedic v0.13.0

First, do no harm. This release closes five ways a program running under your
account could make WinMedic, which runs as Administrator, work for it. And it
ends a dozen cases in which a check reported what was not there or a repair
did more than it should: a working autostart entry deleted, the files of
running programs swept out of the temp folder, a registry backup written over.

---

## Safer

The first five need a program that already runs under your account, without
Administrator rights. Everybody should update.

- **PowerShell modules:** PowerShell looks for modules in
  `Documents\WindowsPowerShell\Modules` first. A module put there ran with
  Administrator rights at the next scan. WinMedic now gives PowerShell
  Windows' own module folders only.
- **curl:** the update check ran `curl.exe` at every start of the window, and
  curl read a `.curlrc` from your user folder, which could make it write a
  file anywhere. curl reads no config file any more.
- **Folders bent somewhere else:** where a folder WinMedic cleans, such as
  `CrashDumps`, a browser cache or `%TEMP%`, had been replaced by a junction,
  the scan measured the folder it pointed at and the repair emptied it.
  A folder that is a link, or lies behind one, is now left alone. That holds
  for a link you set up yourself too, such as a profile moved to another
  drive: WinMedic cannot tell the two apart.
- **Findings from the saved scan:** a finding planted in `last_scan.json`
  could have the repair set any service to Manual and start it. The repair
  takes only the three Windows Update services it checks.
- **The background scan's task** started `%SystemRoot%\System32\conhost.exe`,
  which Windows expands only when the task runs. It is registered with the
  full path now; an existing task is registered again when the window opens.
- **The temp cleanup** deleted every file that was not locked, whatever its
  age: an installer's unpacked files, a document opened out of an archive.
  What was written in the last 24 hours now stays, and the finding no longer
  counts it. A cleanup frees less at once for it.
- **Registry backups:** two repairs in the same key within a second, such as
  two dead autostart entries, left only the second backup, taken after the
  first deletion. Every backup now has a name of its own.
- **Services a repair stopped** stayed stopped until the next restart of
  Windows when the run ended midway: Ctrl+C in `--auto-fix`, or the window
  closing. WinMedic now waits until they run again. **Q** and the window's
  close button no longer end a running repair where it stands: they cancel
  it, and the window closes once it has stopped. Each repair's outcome is
  saved when it finishes.

## Fixed

- **Autostart entries of working programs were deleted** when the program's
  path had a character your Windows' console cannot show: a user folder named
  `Łukasz`, or a Cyrillic or Chinese name. The entry was reported as "without
  its program", ticked, and removed by Repair. The Run keys are read without
  loss now.
- **A cancelled scan** showed "Your PC is in good shape - Health 100 / 100"
  and was saved as the last scan. It now brings the last complete scan back
  and says how many checks had run.
- **Copying did not work:** nothing copied in the window reached Windows. The
  crash report said "The crash log is on the clipboard" while the clipboard
  still held what you had copied before.
- **DISM while Windows waits for a restart:** 0.12.0 fixed this for the WinSxS
  check only. A damaged component store was not reported until the restart,
  and a repair that worked was reported as failed. Such a repair now says
  "Restart Windows to finish it."
- **One blue screen counted as two.** With Windows' default memory dump
  setting, a single crash was reported as "Recurring BSOD history (2
  crashes)", and two crashes reached the threshold for Critical.
- **"DNS servers do not answer"** was raised while websites opened, behind a
  VPN that keeps DNS in its tunnel or with DNS over HTTPS, and its ticked
  repair removed the servers you had set. They are judged only when names do
  not resolve, and the repair changes nothing while they do.
- **"Windows services share their processes"** was a finding on every PC with
  less than 3.5 GB of memory that no repair could clear: there Windows groups
  its services by design.
- **Scheduled tasks:** two results that are no failure, `0x40010004` and
  `0x10000000`, were reported as "last run failed" on every PC.
- **The health score could not reach 100.** Failing tasks of Windows and of
  Office were raised as advice: WinMedic leaves them on, you cannot repair
  them, and each cost two points for good. They are no findings any more; the
  scan's log names them.

## Also

- The window is drawn with egui 0.37. In the dark theme the text of plain
  buttons is a little brighter. The module filter and the checkbox of each
  finding now have a name a screen reader can say.
