# WinMedic v0.15.0

An honest diagnosis. The Defender repair now brings protection back at once
instead of reporting a failure, a repair that could never succeed makes way
for advice, and a stopped service is traced to a driver that is switched off.
The scan and the window do less work for the same result.

---

## New

- **A service that waits for a switched-off driver:** a service that depends
  on a driver stops with error 1068 when that driver is switched off, and
  WinMedic did not say why. It now says so and names the driver. This is
  advice, not a repair: WinMedic does not know which start type the driver
  had. The finding gives the command that lets the service start again.
  Windows keeps some drivers switched off itself; a driver no service waits
  for is not reported.

## Fixed

- **"Microsoft Defender is switched off by policy":** the repair removed the
  policy, but Defender only notices that at Windows' next policy refresh, up
  to 90 minutes later. Until then real-time protection stayed off, the PC
  stayed unprotected, and the repair was reported as failed. The repair now
  has Windows refresh its policies right away. Where this was measured,
  protection was back three seconds later.
- **"N app package(s) are damaged"** came ticked, with a repair that
  registered the packages again. That does not clear the mark Windows keeps
  on such a package, so the repair failed every time it ran. The finding is
  advice now: repair or reset the app under Settings -> Apps -> Installed
  apps -> Advanced options, or reinstall it from the Microsoft Store.

## Faster

- **"Recent activity" and reports** read only the end of WinMedic's history.
  The whole file, up to 5 MB, was read after every scan and repair and
  whenever Settings opened, to show ten entries.
- **While a scan or repair runs,** the window is redrawn 25 times a second.
  The spinner in the status bar had made it redraw at the display's full
  rate, 60 to 165 times a second, beside DISM or SFC.
- **The WinSxS cleanup** no longer has DISM analyse the component store
  before it starts when the scan did so within the last ten minutes. That
  analysis takes a minute or more.
- **The network check** starts PowerShell once for the network adapters, not
  twice.
- **Crash dumps:** only the first 4 KB of each dump are read, not the whole
  file.
