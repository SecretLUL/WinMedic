# WinMedic v0.2.0

Two new modules — **System & Cache Cleaner** and **Auto-Updater** — plus report export, parallel scans, a testable command architecture and a test suite of 335 tests.

The first release the built-in updater can actually see: v0.1.0 was marked as a pre-release and was therefore invisible to `/releases/latest`.

---

## New features

### System & Cache Cleaner with WinSxS deep clean

A new diagnostic module that finds and clears nine space hogs:

| Area | What happens |
| --- | --- |
| **WinSxS component store** | `DISM /AnalyzeComponentStore`, then `StartComponentCleanup` |
| **Delivery Optimization** | `Delete-DeliveryOptimizationCache`, then a manual sweep |
| **Package cache** | Installer leftovers (`RiskScore::High`) |
| **Browser caches** | Chrome, Edge, Firefox, Brave, Opera — every profile included |
| **Setup logs** | `C:\Windows\Panther`, CBS logs |
| **Error reporting** | WER archives and crash dumps |
| **Shader & cert caches** | D3DSCache, CryptnetUrlCache |
| **Recycle Bin** | `Clear-RecycleBin` (`RiskScore::High`) |
| **System temp** | `%TEMP%`, `C:\Windows\Temp` |

Locked files are skipped instead of aborting the run. If **no** file could be removed, the module reports an error rather than an empty success. Package cache and Recycle Bin are rated `RiskScore::High` and **deselected** by default — `--auto-fix` does not empty them unattended. WinSxS results are only evaluated when DISM actually succeeded; the parser understands both German and English DISM output.

### Auto-updater at startup

Queries the latest GitHub release at startup and announces a new version via **[U]** instead of opening a modal from a background event — that way no dialog can swallow a keystroke. The download opens in the browser.

Hardened: full SemVer parsing including pre-release ordering (`1.0.0-beta` < `1.0.0`), release URLs must start with `https://github.com/` and must not contain shell metacharacters, launching goes through `explorer.exe` rather than `cmd /c start`, and drafts and pre-releases are skipped.

### Report export

Findings as **HTML**, **Markdown** or **JSON** — via `--output <path>` or **[E]** in the TUI.

### Run control

Cancellable scans and repairs, rollback, a settings tab, a dry-run mode and meaningful exit codes for scripting.

## Interface

- Issue list with a severity filter **[c/w/i]**, module filter **[m]**, live search **[/]** and reset **[x]**
- Log view as a ring buffer (max. 2000 lines) with **PgUp/PgDn/Home/End** — long runs no longer eat memory
- Live sub-step logs during scans, SMART telemetry for drives
- Dashboard cards wrap long module names instead of truncating them
- Custom icon and PE version metadata in `winmedic.exe`

---

## Performance

- Modules scan **in parallel** through a `tokio::JoinSet` instead of sequentially
- Directory walks run in `spawn_blocking` and no longer block the async runtime
- The audit log is an append-only **JSONL** file with O(1) writes and automatic rotation; existing logs are migrated

---

## Safety & correctness

- **Admin detection** via the Win32 `CheckTokenMembership` call, with an elevation prompt in the TUI
- **`CleanerPaths`** as an injectable filesystem seam: tests run in a sandbox instead of against real browser caches, WER archives and `C:\Windows\Panther`
- **`windows_updates`**: file sizes were truncated to whole megabytes, so everything below 1 MB went missing — fixed
- The update check was pulled out of `App::new`; constructing an `App` no longer performs network I/O
- A shared directory walker in `utils::fs_stats`, used by `system_cleaner`, `storage` and `windows_updates`

---

## Architecture & tests

- A **`CommandRunner` trait** with `SystemCommandRunner` and `MockCommandRunner` — modules can be tested deterministically without real system calls
- **335 tests**: 77 unit tests plus 258 integration tests across four tiers (features, boundaries, combinations, scenarios) and several adversarial suites
- CI checks formatting, Clippy (`-D warnings`), tests and the release build on `windows-latest`

---

## Release process

Pre-release marking now follows SemVer: only tags with a suffix (`v0.3.0-rc1`) are pre-releases. Previously **every** tag before v1.0 counted as a pre-release, which meant `/releases/latest` returned nothing and the updater never found an update.

Release notes come from `docs/release-notes/<tag>.md`; if the file is missing, GitHub generates the commit list.
